# build

The published artifacts: **`mesh-ui.html`** (the estate view) and **`mesh-spec-ui.html`** (the
spec viewer) — each one self-contained page with every script, style and asset inlined.

It is committed rather than built by each consumer because the consumers are not JavaScript
projects. `Benzene.Mesh.Ui` embeds this file as a .NET resource and serves it from inside a running
service; the website vendors it as a demo. Making either of them run `npm ci && npm run build` to
obtain an HTML file would put a Node toolchain in the critical path of a NuGet package build.

A committed build output can drift from its source silently, so CI rebuilds it on every push and
fails if the bytes differ from what is committed here. The build is deterministic — same lockfile,
same input, same output — which is what makes that check meaningful rather than flaky.

**Do not edit this file.** Change `src/`, run `npm run build`, and copy `dist/index.html` here:

```sh
npm run build && cp dist/index.html build/mesh-ui.html
```

## Who vendors it

| Consumer | Path | How it is served |
|---|---|---|
| `benzene-dotnet` | `src/Benzene.Mesh.Ui/mesh-ui.html` | Embedded resource, served by `MeshUiMiddleware` |
| `Benzene` | `mesh-ui/mesh-ui.html` | The canonical cross-language copy |
| `Benzene` | `website/demos/mesh/index.html` | The live demo on benzene.app |

The host may inject `data-manifest-url`, `data-fleet-url` and `data-annotations-url` onto the
`<html>` element; the page reads all three. `MeshUiPage.GetHtml` does this by rewriting the literal
string `<html lang="en">`, so that opening tag must stay exactly as the build emits it.
